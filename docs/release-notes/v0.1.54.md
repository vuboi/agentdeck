### What's new

- **Tasks menu.** Settings > Tasks has two tabs. Fallback and continue holds the "keep working when an agent fails" switch, auto-continue, and the order of agents to carry on with. Each row takes one model and can be dragged to reorder.
- **Task roles, in seven groups.** Pick one or more agents or models for each kind of work: Read (pictures, files and documents), Research (web search, papers and sources), Plan, Review (code and security), Write (docs, tests and emails), Text (summarize and translate), and Logic and math. Each role keeps its picks when it is switched off. A master switch turns every role off at once without losing them. Settings saved under the old role names move to the new groups on first start.
- **Pictures read by a chosen model.** The models picked for Read read each picture before the agent sees it, in the order you picked them. Copilot, OpenCode and Antigravity models can read pictures as well as Claude and connectors. Nothing is picked by default: the main agent then reads the pictures itself.
- **Routed delegation.** `delegate_task` takes a `role` argument. With a role, AgentDeck sends the work to the first available agent set for that role, and the chat shows the role while it runs (for example "Searching the web") and once it is done.
- **Settings layout.** CLI extensions (OfficeCLI) has its own entry. Limit alerts, Replies, Computer use, Sync and Debug are grouped under System, and About is back as its own entry. The debug log can be switched off in Debug; it is on by default.
- **Keyboard in the message box.** Enter queues the message. Alt+Enter sends it next, right after the current answer. Ctrl/Cmd+Enter stops the answer that runs and sends the message straight after it.

### Fixes

- **Send now and Ctrl/Cmd+Enter send.** While the agent works, both used to queue the message without stopping the answer, so nothing was sent. They now stop the running answer and send the message next. If the first answer of a chat is stopped before it wrote anything, the next message starts a new conversation instead of resuming a thread that does not exist yet ("no rollout found").
- **Chats stay in their project.** A chat that had not written its history file yet, or whose project holds only local chats, was moved to This computer. It now stays in its project.
- **Provider errors reset the right conversation.** The "conversation not found" handling covers Codex, Claude, OpenCode, Antigravity and Copilot, and resets the conversation of the agent that is running, including after a switch to another agent in the same chat.
- **Picture reading that fails explains why.** The OpenCode error is shown in the flow log instead of a generic message. A model that fails (for example an expired key) is left out for 10 minutes, so the next turns use the next model. The turn that failed still goes to the main agent.
- **Settings tabs keep their place.** The tab strips of Connectors, Tasks and System stay fixed above their content, with a divider. Only the content scrolls, and the strip no longer shifts when you scroll. Icons and labels line up in the tabs, and the Tasks tabs have icons like Connectors.
- **Task roles keep what you set.** Switching a role off and back on shows the same models again. Empty rows stay while you move between menus, and are dropped on reload.
