### What's new

- **Claude switches model without a restart:** changing the model of a Claude chat is sent to the CLI that is already running (`set_model`), so the conversation and its context stay and the next message does not wait for a new start.
- **Model fallback is shown:** when Claude moves a turn to another model (a refusal or a model that is unavailable), the reply says so. If the whole chat moved, the chat's model follows it; a fallback of one sub-agent or side question leaves the chat's model as it was.
- **Extensions in Browser Preview:** the page toolbar has an Extensions menu. Each extension shows its icon, is turned on or off, can be reloaded or removed, and opens its toolbar page in a new tab. "Add unpacked extension…" works with no page open: the extension loads when the next page opens.
- **Store finds skills:** Discover reads the skills of the Anthropic skills repository by default, and each skill shows its description. Skills can be given to OpenCode and Antigravity as well as Claude and Codex.
- **Running tools keep the turn alive:** while a tool call runs (a long build or test), the no-output stall check waits up to two hours instead of ten minutes.
- **Prewarm for recent chats:** the two most recent chats start their CLI a few seconds after start-up, so the first message to them does not wait.

### Fixes

- **Messages sent during an account switch** wait in order and go out whole: a delegated worker keeps its brief, and a recovery turn is not sent as an empty message.
- **Conversation history is sent once** after a model or account change (it was sent twice to other agents' turns).
- **Worker slots are returned** when a delegated task ends before its slot was granted, so a stopped task no longer holds one of the three places until restart.
- **Footer waits for the text:** the copy, fork and time line appears once the reply text is fully drawn, not while it is still being written.
- **A model fallback that the picker does not list** no longer moves the chat onto an unrelated model.
- **Antigravity browser link** is remembered only when adding it succeeded, so a failed add is tried again on the next turn.
- **Store skeleton** no longer shifts the list when it turns into the real rows; the refresh keeps the list in place.
- **Store install and uninstall dialogs** use the app's standard confirm dialog; the plugin on/off switch no longer shows the uninstall button as busy.
- **MCP servers** show each agent's logo next to its name.
- **Watchdog and stop:** an interrupted Claude or Codex turn keeps its process; a failed Codex turn no longer drops the warm server.
