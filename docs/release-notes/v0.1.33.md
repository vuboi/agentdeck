### What's new

- **Shell guard, two levels:** a shell command is judged before the permission mode and before any earlier "always allow".
  - **Heavy commands are refused in every mode**, yolo included, and the agent is told why: erasing a disk, a partition, a system folder, a drive or a database (`mkfs`, `format C:`, `diskpart`, `dd` onto a device, `rm -rf /`, `DROP DATABASE`, `TRUNCATE`, `FLUSHALL`, `migrate reset`…), a `DELETE` or `UPDATE` with no `WHERE`, malware and what it does (credential dumpers, miners, reverse shells, encoded or download-and-run PowerShell, switching off the antivirus, destroying backups, sending keys out).
  - **Risky commands are asked about every time**, even in a mode that approves commands and even after an earlier "always allow", with a "⚠" line on the card saying what to look at: recursive deletes (`rm -rf *`, `rm -rf node_modules`), `sudo`, `git push --force`, `git reset --hard`, `git clean`, deleting branches, `curl … | sh`, killing processes, `docker`/`kubectl`/`terraform`/cloud deletes and deploys, publishing a package, an `INSERT` or a migration on a database. Plan mode still refuses every command.
  - It covers the custom chat (local models) and Copilot. Claude also gets deny rules for the heaviest starts (`--disallowedTools`), because it runs its own commands. Codex, OpenCode and Antigravity decide in their own CLIs, as before.
- **`/security`:** a built-in command that asks the agent for a read-only security audit of the application across every language and layer.

### Fixes

- **A command the user had allowed once could run again without a question even when it had become dangerous:** a risky command now asks every time, whatever was allowed before.

### Notes

- The guard matches on text. A command written in a roundabout way (variables, encodings) can get past it: it is a net for mistakes, not a security boundary.
